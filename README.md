# Демонстрационная версия Telegram-помощника по атласу

В архив включены разрешённые владельцем 20 оригинальных статей, готовые SQLite/FTS5 и ChromaDB с 49 поисковыми документами и реальными векторами. Полный DOCX не включён и для работы не нужен. Базы уже готовы: **импорт, разбиение текста и повторную индексацию запускать не требуется**.

Простое описание задумки и вариантов общения: `TEACHER_SUMMARY.md`.

## Быстрый запуск на другом компьютере

Распакуйте всю папку `neuro-atlas-rag-demo` в свой каталог. Не переносите только `main.py`: папка `data/` и остальные модули должны оставаться рядом. Проверено на Windows, Python 3.12.3 и версиях библиотек из `requirements-tested.txt`. Установка в совершенно новом окружении и другая ОС отдельно не проверялись.

В PowerShell из корня распакованной папки:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-tested.txt
```

Установка библиотек требует Интернета, но не выполняет запросы генерации или индексации. Набор фиксирует проверенные прямые зависимости; это не полный транзитивный lock.

### Сначала — проверка без ключей и расходов

До создания `.env`:

```powershell
.\.venv\Scripts\python.exe -B -m tools.verify_demo
.\.venv\Scripts\python.exe -B -m tools.test_demo
```

Первая команда сверяет SHA-256 готовых данных, записи/метаданные, прямой и обратный запросы, три режима поиска и кэш без DOCX. Она использует уже сохранённые векторы контрольных вопросов, mock-ответы модели и временную копию баз; внешняя сеть заблокирована. Вторая запускает применимые автоматические тесты. Отчёты появляются в `reports/`.

Пять прежних тестов импорта полного исходного DOCX намеренно исключены из демонстрационного запуска. Искусственные DOCX-примеры парсера продолжают проверяться. Старый `tools.test_offline` предназначен для полной рабочей копии с DOCX; для этой поставки используйте `tools.test_demo`.

### Собственный ключ и отдельный Telegram-бот

1. Создайте собственного бота через официальный `@BotFather` в Telegram и получите его токен. Не используйте токен владельца проекта.
2. Подготовьте собственный OpenAI API-ключ с доступом к выбранным моделям и доступным API-балансом.
3. Скопируйте `.env.example` в `.env` и заполните значения локально:

```ini
TELEGRAM_BOT_TOKEN=
TELEGRAM_ALLOWED_USER_IDS=
OPENAI_API_KEY=
LLM_PROVIDER=openai
OPENAI_MODEL=gpt-4o-mini
EMBEDDING_PROVIDER=openai
EMBEDDING_MODEL=text-embedding-3-small
```

В `TELEGRAM_ALLOWED_USER_IDS` укажите свой числовой Telegram user ID, не username и не ID бота. Можно перечислить несколько ID через запятую. Пустой список пользователей закрывает доступ. Пустой `TELEGRAM_ALLOWED_CHAT_IDS` допускает только личные чаты разрешённых пользователей. Не отправляйте заполненную `.env` вместе с архивом.

4. Осознанно разрешив расходы за ответы и новые поисковые вопросы, запустите:

```powershell
.\.venv\Scripts\python.exe -B main.py --run-telegram --allow-paid
```

Запуск без этих двух флагов не включает Telegram. Ключи читаются из `.env` рядом с `main.py`; значения окружения имеют приоритет. Не требуется прописывать пути прежнего компьютера. При необходимости HTTP-клиенты используют настройки прокси окружения. TLS включён.

Готовые векторы документов повторно не рассчитываются. Новые вопросы могут требовать платного эмбеддинга вопроса; ответы модели также оплачиваются. Сохранённые векторы десяти контрольных вопросов позволяют проверить поиск офлайн, но не делают реальные ответы LLM бесплатными. Автоматического денежного лимита бот не устанавливает.

Остановка — Ctrl+C. Не запускайте две копии с одним токеном. При старте старые ожидающие сообщения сбрасываются. SQLite-кэш ответов создаётся пустым при первом обращении; чужой истории и чужих готовых ответов в поставке нет.

## Как пользоваться

Команды: `/start`, `/help`, `/stats`, `/clear`. Последняя очищает текущий диалог. Примеры вопросов: «Большие глаза», «Физическая и психическая выносливость», «Фотографии результата». После ответа можно написать «А что это означает?» или «Покажи оригинал». Источник обозначается названием статьи/раздела; полный DOCX для просмотра канонического текста не нужен. Не все формулировки распознаются: бот отказывается, если подтверждение не найдено.

## Что находится внутри

- `data/atlas.sqlite3`: 20 канонических статей, исходные абзацы и необходимые заголовки разделов.
- `data/atlas_search.sqlite3`: 49 готовых поисковых документов и FTS5.
- `data/chroma_openai/`: одна готовая коллекция с 49 векторами, 1536 измерений.
- Проверенные связи, политики подтверждений/пояснений, манифест выборки и векторы контрольных вопросов.
- Код, тесты, документация, пустой конфигурационный шаблон и агрегированные отчёты.

Сохранены исходные ID, версии и метаданные. Имя DOCX в источниках — указание происхождения, а не требование наличия файла. Фактическая целостность проверяется по включённым каноническим текстам, политикам и SHA-256 данных.

`DATA_MANIFEST.json` содержит контрольные суммы готовых данных, `FILE_MANIFEST.json` — файлов всей поставки, кроме самого манифеста. Не выполняйте `tools.ingest_atlas`, `tools.index_atlas`, `tools.real_embeddings` или старый корпоративный импортер для первого запуска: все базы уже включены. Полный атлас и новые документы — отдельная задача с проверкой границ и связей.

## Провайдеры и ограничения

Рабочий демонстрационный путь — OpenAI. Встроенный адаптер GigaChat использует официальный SDK и проверку TLS; модель ответов переключается через `LLM_PROVIDER`, не изменяя индекс. Однако живой GigaChat не проверен и фиксированный адрес API отличается от исходного ТЗ. Он не заявляется готовым вариантом этой демонстрации. Переключение требует собственных credentials, доверенного CA при необходимости и отдельной проверки совместимости; SDK устанавливается только по потребности из `requirements-gigachat.txt`.

Пояснения ограничены проверенными переформулировками источника, свободный пересказ не принимается автоматически. Поиск оценён на небольшом контрольном наборе. История диалога хранится в памяти процесса. Старые модули исходного проекта сохранены, но запускать следует только описанную точку входа; legacy-настройки GigaChat с отключённым TLS не используются.

Владелец разрешил публичную публикацию только включённых 20 статей и готовых демонстрационных данных. Полный исходный DOCX и остальные статьи не включены. `.gitignore` исключает секреты, пользовательский кэш и журналы, но допускает конкретные файлы готовой демонстрационной базы. Разрешение не означает автоматического распространения лицензии на весь атлас.
